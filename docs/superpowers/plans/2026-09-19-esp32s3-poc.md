# ESP32-S3 Phase 0 PoC Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Bring up GP2040-CE on a generic ESP32-S3 DevKitC-1-class board with USB-device HID/XInput gamepad plus BLE HID gamepad (Xbox-layout report) as a mutually-exclusive input mode, behind a new HAL seam, with RP2040 still building.

**Architecture:** Introduce `hal/` interfaces with `hal_rp2040` (Pico SDK wrappers) and `hal_esp32s3` (ESP-IDF: GPIO, ADC-oneshot, LEDC, RMT, esp_timer) backends; add `INPUT_MODE_BLUETOOTH = 15` plus a `GPDriver::usesUSB()` seam (default true, Bluetooth false) so `tud_init`/`tud_task` are skipped in BT mode; add a header-only Xbox-layout BLE report builder (host-unit-tested) and a `TransportRouter` single-active stub that later hosts dual USB+BT. ESP-IDF build lives in `esp32-s3/` (partitions, sdkconfig.defaults, README). No USB host, no auth, no webconfig in Phase 0 — config runs from compiled defaults, persistence lands in Phase 1.

**Tech Stack:** ESP-IDF 5.x (`idf.py`), xtensa-esp32s3-elf-gcc, `espressif/tinyusb` (device) + NimBLE (HOGP), host g++ for report unit tests, existing Pico-SDK CMake for RP2040 regression.

**Spec:** Approved in chat 2026-09-19 (full native S3 port + BLE HID Option 1 now, dual-transport/USB-ECM/classic-ESP32 parked). No separate spec doc — this plan is the authority; decisions: DevKitC-1-class ref board (GPIO19/20 USB-reserved, strapping 0/3/45/46 reserved), WiFi-AP webconfig later, Xbox/Series-X-style BLE report layout.

## Global Constraints

- RP2040 `main` build must keep compiling — every HAL change keeps the Pico path green (verified via existing CMake build / CI).
- `proto/*.proto` wire layout is append-only — new enum values only, never renumber (nanopb footer/CRC compatibility for Phase 1 storage).
- No `gpio_get_all()`-style bulk reads on S3 — per-pin `gpio_get_level()` loops (RP2040 idiom has no S3 equivalent).
- BLE HID is BLE-only (S3 has no Classic BT) — targets PC/Android/iOS; console BT modes are out of scope.
- BLE connection interval floor is 7.5 ms (~133 Hz notify) — never promise 1000 Hz over BLE; USB path keeps 1000 Hz polling.
- YAGNI: no dual-transport logic, no NVS bonding UI, no webconfig in Phase 0 — stubs and seams only.

- [ ] **Step 1: Write the header-only builder `headers/drivers/bluetooth/ble_gamepad_report.h`**

```cpp
#ifndef _BLE_GAMEPAD_REPORT_H_
#define _BLE_GAMEPAD_REPORT_H_

#include <stdint.h>

// Xbox/Series-X control set over a standard HID gamepad report:
// 11 buttons (A,B,X,Y,LB,RB,Back,Start,LS,RS,Guide), 2 analog triggers, 4 stick axes.
struct BleGamepadReport {
    uint16_t buttons; // bit0=A bit1=B bit2=X bit3=Y bit4=LB bit5=RB bit6=Back bit7=Start bit8=LS bit9=RS bit10=Guide
    uint8_t  leftTrigger;
    uint8_t  rightTrigger;
    int16_t  leftX;
    int16_t  leftY;
    int16_t  rightX;
    int16_t  rightY;
};

inline BleGamepadReport buildBleGamepadReport(uint16_t buttons, uint8_t lt, uint8_t rt,
                                              int16_t lx, int16_t ly, int16_t rx, int16_t ry) {
    BleGamepadReport r;
    r.buttons = buttons & 0x07FFu;
    r.leftTrigger = lt;
    r.rightTrigger = rt;
    r.leftX = lx;
    r.leftY = ly;
    r.rightX = rx;
    r.rightY = ry;
    return r;
}

#endif
```

No SDK includes — this file must compile with host g++.

- [ ] **Step 2: Write the failing test `tests/host/test_ble_report.cpp`**

    // A(0) + RB(5) + Guide(10) pressed, half left trigger, sticks at extremes
