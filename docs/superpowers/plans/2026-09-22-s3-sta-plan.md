# S3 WiFi STA Mode Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Join a home network as a WiFi station (concurrent with the config AP) with UI-configured credentials, scope-gated boot behavior, and LAN-reachable web UI.

**Architecture:** Three new `optional` proto fields feed the existing defaults machinery; STA lifecycle (APSTA mode, DHCP client, event-driven backoff) lives beside the AP code in the S3-only webconfig TU; a small status endpoint serves the UI; React gains a Home Network section mirroring the AP fields. Display (§6 of spec) is explicitly out — follow-up plan when OLED hardware arrives.

**Tech Stack:** ESP-IDF v5.4 (WiFi APSTA, esp_netif DHCP client, esp_event, esp_timer one-shot, NVS), nanopb, ArduinoJson (vendored), React bundle (prebuilt `www/build`), Pico SDK 2.3.1 + ARM GCC (regression only), host g++ (existing tests).

**Spec:** `docs/superpowers/specs/2026-09-22-s3-sta-mode-design.md` — this plan argues from the spec; executors read both.

### Task 2: STA lifecycle + boot integration

**Files:**
- Modify: `src/webconfig_s3.cpp` (S3-only TU)

**Interfaces:**
- Consumes: Task 1 fields/defaults.
- Produces: STA joined whenever wanted; `s3_sta_connected()`, `s3_sta_ip()` (or equivalent names — Task 3 depends on exact names, so report them verbatim) for the status endpoint.

- [ ] **Step 1: STA wanted predicate + mode matrix**

```cpp
// STA is wanted when mode is Always-on, or in a webconfig session when Webconfig-only.
static bool s3_sta_wanted(bool webconfigSessionActive);
// WiFi mode matrix (call after the AP decision, same setup path):
//   AP wanted + STA wanted -> WIFI_MODE_APSTA (AP config + STA config)
//   AP only               -> WIFI_MODE_AP (existing path untouched)
//   STA only              -> WIFI_MODE_STA
//   neither               -> no WiFi at all (existing behavior)
```
NVS/netif/event-loop init must run when STA-only too (today it lives in the AP path — hoist the shared init so STA-only works).

- [ ] **Step 2: Join + event-driven backoff (no extra task)**

```cpp
esp_wifi_set_mode(<matrix result>); // AP config as today when AP wanted
wifi_config_t sta = {}; strncpy((char*)sta.sta.ssid, ssid, 32); strncpy((char*)sta.sta.password, pass, 64);
esp_wifi_set_config(WIFI_IF_STA, &sta);
esp_event_handler_instance_register(WIFI_EVENT, ESP_EVENT_ANY_ID, s3_wifi_handler, ...);
esp_event_handler_instance_register(IP_EVENT, IP_EVENT_STA_GOT_IP, s3_wifi_handler, ...);
esp_wifi_start(); // AP path already starts; start once if either wanted
esp_wifi_connect(); // initial attempt; further attempts driven by events
```
Handler: on `WIFI_EVENT_STA_DISCONNECTED`, arm an `esp_timer` one-shot with backoff delays `{5, 10, 20, 40, 80, 160, 300, 300, ...}` seconds (cap 300, reset to 5 on `IP_EVENT_STA_GOT_IP`); the timer callback calls `esp_wifi_connect()` (guard: skip if STA no longer wanted or already connected). Track state in file-statics: connected bool, dotted IP string (from `IP_EVENT_STA_GOT_IP` `ip_event_got_ip_t`), last failure. AP lifecycle fully independent — never touch AP state from STA paths. Empty SSID → STA never attempted (treat like Off).

- [ ] **Step 3: Boot wiring**

In `GP2040::setup` S3 region (near the AP decision): STA joins at boot when mode is Always-on, or in any webconfig session (L1-hold, toggle, CONFIG+WiFi-pref) when Webconfig-only; Off never joins. Gamepad/USB loop untouched.

- [ ] **Step 4: Verify by build (live deferred to Task 4 E2E)**

S3 + Pico builds green. State explicitly in the report that live join behavior is verified in Task 4 end-to-end.

- [ ] **Step 5: Commit**

```bash
git add src/webconfig_s3.cpp
git commit -m "feat(s3-sta): STA lifecycle + boot integration"
```
