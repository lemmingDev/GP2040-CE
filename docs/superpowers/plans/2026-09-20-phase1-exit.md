## esp_hidd verdict: adopt esp_hidd (NimBLE transport)

Read: `~/sdks/esp-idf/examples/bluetooth/esp_hid_device/` (report maps,
GAP/advertising, `esp_hidd_dev_init` with NimBLE transport, appearances).
Reference: `components/esp_hid/include/esp_hidd.h` (`esp_hidd_dev_init`,
`esp_hidd_dev_input_set`), `esp_hid_common.h` (`ESP_HID_APPEARANCE_GAMEPAD`).

Reasons:
1. The hand-rolled NimBLE GATT 0x1812 table in `BluetoothDriver.cpp` is
   100% assumption — every NimBLE symbol carries a `TBD-Task8-verify` marker,
   it has never compiled, and IDF 5.4 NimBLE may not match (init-call shape,
   store-status callback, `ble_gatt_svc_def` field order all guessed).
2. `esp_hidd` is Espressif-maintained, pinned to our IDF v5.4, example-backed,
   and supports the NimBLE transport (`CONFIG_BT_NIMBLE_ENABLED` path,
   `esp_nimble_enable` + `ble_store_config_init`) — no Bluedroid needed.
3. Gamepad appearance exists (`ESP_HID_APPEARANCE_GAMEPAD 0x03C4`); report
   maps are caller-supplied raw bytes, so the existing gamepad
   `bleHidReportMap` ports directly; advertising via
   `esp_hid_ble_gap_adv_init` / `esp_hid_ble_gap_adv_start`.
4. Phase-1 constraints survive on top: change-only notify stays as the
   existing `memcmp` gate above `esp_hidd_dev_input_set`; no bonding UI
   (Just Works / NoIO as today).
5. Migration is contained to the `ESP_PLATFORM` sections of
   `BluetoothDriver.cpp`; Pico path, `bleAxisFromRaw`, and the report struct
   are untouched.

Migration sketch (hardware-validation task owns the rewrite):
```c
static esp_hid_device_config_t hid_cfg = { .vendor_id = 0x16C0,
  .product_id = 0x05DF, .version = 0x0100, .device_name = "GP2040-CE-BLE",
  .manufacturer_name = "GP2040-CE", .serial_number = "1",
  .report_maps = gamepad_maps, .report_maps_len = 1 };
esp_hid_gap_init(HID_DEV_MODE);
esp_hid_ble_gap_adv_init(ESP_HID_APPEARANCE_GAMEPAD, hid_cfg.device_name);
esp_hidd_dev_init(&hid_cfg, ESP_HID_TRANSPORT_BLE, hidd_cb, &hid_dev);
// per-frame: if (memcmp(&r, &lastSent, sizeof r))
//   esp_hidd_dev_input_set(hid_dev, 0, GAMEPAD_RPT_ID, (uint8_t*)&r, sizeof r);
```
Adopt risks to clear on hardware: Kconfig (`CONFIG_BT_NIMBLE_ENABLED`,
`CONFIG_BT_NIMBLE_NVS_PERSIST` for the store), report-ID/`map_index`
plumbing, OUTPUT/FEATURE (rumble/LED) handling via `ESP_HIDD_OUTPUT_EVENT`

## Hardware session notes (2026-09-20)

- First boot aborted in `FlashPROM::commit()` (`esp_timer_stop` on a never-started
  timer); fixed by `is_active` guard. Second boot tripped the task watchdog on
  `gp2040aux` (tight loop); `vTaskDelay(pdMS_TO_TICKS(1))` did NOT fix it —
  at the default 100 Hz tick rate that is 0 ticks (mere yield, still starves
  IDLE). Fixed with `vTaskDelay(1)` (exactly one tick at any rate).
- Native-USB bring-up: raw `tud_init()` alone never enumerates on S3 (OTG
  peripheral/PHY/pins stay with USB-Serial/JTAG). Fix `e99afb9` enables the
  internal-PHY OTG device before `tud_init`. Observable side effect, as
  predicted: the COM port (Serial/JTAG) goes silent once OTG owns GPIO19/20 —
  logs and gamepad are mutually exclusive on one cable. Keep a known-good
  `.bin` + esptool handy before flashing experiments that may kill the log
  channel.
- Cable map on this board: whichever USB-C is cabled carries the active
  function; device presents `USB\VID_045E&PID_028E` (XInput) with driver OK.

## First-hardware validation procedures

Board: ESP32-S3-DevKitC-1. S3 USB = GPIO 19/20 (never assign); strapping 0/3
hands-off (fresh-defaults pin table keeps RESERVED/ASSIGNED non-positive).

1. Flash + monitor:
   `wsl --exec bash -c 'bash ~/s3build.sh flash'` (BOOT+RESET into download
   mode if needed), then `bash ~/s3build.sh monitor`. Expect normal gamepad
   start, no `ESP_ERROR_CHECK` aborts (`gpconfig` partition label present).
2. USB HID: set input mode HID (default fallback), confirm enumeration +
   button/stick inputs on the host. Repeat per driver mode: XInput, Switch,
   PS3, Keyboard, PS4, PS5, XBOne, MDMini, NeoGeo, PCEngine, Egret, Astro,
   PSClassic, XboxOriginal — each must enumerate with its descriptors.
   (Bluetooth mode falls back to HID on S3 — expected, Ruling W3.)
3. Config round-trip (Task-3 procedure; Task-3c LANDED: real ConfigUtils
    load/save on the gpconfig partition, save shim removed — run the full
    persistence validation now): change a setting (input-mode hotkey), wait
    >50 ms, press RESET; confirm the setting persisted. Repeat with a second
   change within 50 ms to exercise commit coalescing (single erase/program
   cycle). Factory-reset path: trigger reset, confirm reboot with zeroed
   config (fresh defaults) — validates `reset()` → `commit()` → erase.
4. Display + outputs: confirm the OLED buttons screen tracks inputs;
   NeoPixel animation, buzzer tones, and rumble motors respond. Known
   watch-items: LEDC shared-channel overlap under concurrent addons is
   last-writer-wins (Ruling C1); `GPIO_PIN_15`/`GPIO_PIN_28` are
   ASSIGNED_TO_ADDON in the S3 board table (also TURBO_LED_PIN/BUTTON_A2 on
   15) — confirm no conflict with USB/strapping on the real board.
5. BLE (after the esp_hidd migration above lands): advertise as gamepad
   (appearance 0x03C4), pair with Just Works, confirm change-only input
   reports ≤ ~133 Hz and clean disconnect/re-advertise.
