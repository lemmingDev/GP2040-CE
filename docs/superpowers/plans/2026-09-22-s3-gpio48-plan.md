# S3 48-Pin GPIO Support Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Expose ESP32-S3 GPIO 0–48 for button mapping (minus invalid/special pins) by adopting upstream #1655's flat model, with 64-bit masks throughout.

**Architecture:** Board policy data (48-entry table + invalid/reserved/note sets) in `BoardConfig.h`; `NUM_BANK0_GPIOS` 30→49 S3-only; proto tables widened to fit; every pin-to-bit shift made 64-bit; legacy 30-entry configs wiped on upgrade (single flashed board, no migration matrix); UI reflows from the API count automatically.

**Tech Stack:** ESP-IDF v5.4 (S3 build), Pico SDK 2.3.1 + ARM GCC 14.2 (regression only), nanopb, host g++ (pin-policy unit test).

**Spec:** `docs/superpowers/specs/2026-09-22-s3-gpio48-design.md` — this plan argues from the spec; executors read both.

## Global Constraints

- S3 tree builds with `bash ~/s3build.sh build` in `~/gp2040-s3build` (plain-source WSL copy; sync changed files per batch; full re-sync before final builds).
- Pico regression stays green: `cmake --build build` in `~/gp2040-wsl` (fetch/reset there only, never the worktree).
- S3-only changes via board header, `#if defined(ESP_PLATFORM)`, or S3 TUs; Pico behavior byte-identical (its pins stay <32, its tables stay 30/48).
- No 32-bit pin shifts anywhere S3 compiles: `Mask_t{1} << pin` (`Mask_t` is `uint64_t`), never `1 << pin` / `1u << pin` / `1UL << pin` on pin numbers.
- Commit after every task; push at the end. Display/USB work untouched.

### Task 1: Board policy data + pin-policy test

**Files:**
- Modify: `configs/ESP32S3DevKitC1/BoardConfig.h`, `headers/helper.h`

**Interfaces:**
- Consumes: nothing.
- Produces: `NUM_BANK0_GPIOS 49`; `GPIO_PIN_30`…`GPIO_PIN_48` per policy below; S3 `isValidPin` rejects 22–34; used by Tasks 2–5.

Policy table (append to the board header, same `GPIO_PIN_XX` macro style):
- `GPIO_PIN_30`…`GPIO_PIN_32`: NONE (nonexistent package pins).
- `GPIO_PIN_33`…`GPIO_PIN_37`: RESERVED (octal flash/PSRAM on this module; variant-conditional by design, hardcoded for this board).
- `GPIO_PIN_38`: NONE (pixel hardware present but data pin unassigned by default; user-assignable — NONE keeps it out of the button table until assigned? NO: NONE means "maps nothing" but still listed. Assignability comes from the UI offering every non-invalid pin. Set 38 to NONE with a comment so it shows but maps nothing until the user picks it... wait — NONE pins still appear as rows; user CAN assign actions to NONE rows? On Pico, NONE rows are assignable (action defaults NONE, user picks). Yes: NONE = available row defaulting to nothing. Correct for 38 AND for 35-48 spares.)
- `GPIO_PIN_39`: TURBO (already assigned), `40`/`41`/`42`: NONE-but-present? 41/42 are ASSIGNED_TO_ADDON (I2C0). 39 TURBO, 40 NONE. Keep existing assignments; extend pattern.
- `GPIO_PIN_43`/`44`: RESERVED (UART0 console — mapping buttons here kills COM7 flash/logs).
- `GPIO_PIN_45`/`46`: RESERVED (strapping: flash-voltage select; 46 input-only caveat on some revisions — comment it).
- `GPIO_PIN_47`/`48`: NONE (available spares).
- `GPIO_PIN_19`/`20`: already RESERVED (native USB) — keep.
- `GPIO_PIN_0`: stays assigned (A1/Guide) with existing boot comment; `GPIO_PIN_3`: RESERVED (strapping, JTAG-source) — keep.
- `isValidPin` S3 branch: `0<=pin<=48 && pin!=19 && pin!=20 && !(pin>=22 && pin<=34)`.
- Pixel: `BOARD_LEDS_PIN` stays `-1` (unassigned); note GPIO38 in its comment.
- Pin notes table for the UI (board header, generic shape for future boards):
```cpp
// Note text surfaced in the pin-mapping UI; absent pin = no note.
static const char *const PIN_NOTES[] = { /* index = GPIO number, 49 entries, "" or note */ };
```
with non-empty entries exactly: `0` (boot caveat), `3`/`45`/`46` (strapping caveats), `19`/`20` (native USB), `35`/`36`/`37` (flash-octal, this module), `43`/`44` (UART0 console). All other 42 entries `""`.
- `tests/host/test_pinpolicy.cpp` asserts: macro values (NONE/RESERVED/assigned), `NUM_BANK0_GPIOS == 49`, and the PIN_NOTES entries above verbatim (include ONLY `BoardConfig.h` — verify self-containment first; if it drags heavy includes, assert via a compile-only TU instead).
