# S3 48-Pin GPIO Support — Design

Date: 2026-09-22. Status: sections §1–§5 approved.
Approach A (adopt upstream #1655 flat). One-shot migration: this is the
only board ever flashed, no fleet to support, no downgrade path.

## Context

Upstream PR #1655 (in our tree) expanded pin storage 30→48 for
RP2350B and made the web UI reflow from the API pin count, but our S3
port still defines `NUM_BANK0_GPIOS 30`: the pin page shows GP0–GP29
only. ESP32-S3 has GPIO 0–48 with holes and special-purpose pins, so
adoption needs S3 policy data, not just the define. Related upstream
reading: `https://github.com/OpenStickCommunity/GP2040-CE/pull/1655`.

## Decisions (locked with human partner)

- Adopt #1655 flat (not a bolt-on second bank).
- Pin policy: 0–21 + 35–48 usable; invalid {22…34}; reserved 19/20
  (USB), 35–37 (flash-octal on this module), 43/44 (console); notes on
  0 (boot), 3/45/46 (strapping); pixel data pin unassigned by default
  (GPIO38 mappable).
- Policy-as-data from the board header in generic shape, so future
  extra-pin boards adopt the same layout.
- 35–37 unavailability is module-specific (octal flash/PSRAM); keep the
  mechanism variant-aware, not hardcoded universal.

## §1 Table extension + policy data

`NUM_BANK0_GPIOS` 30→48, S3 only. All pin-indexed tables to 48 entries
(functional mappings, migration staging, debounce set). No proto change
(`max_count = 48` already). Animation color arrays already 12 (= 48/4).

## §2 Mask audit

Every `1 << pin` / `1UL << pin` site becomes 64-bit (`Mask_t{1} << pin`;
`Mask_t` already `uint64_t`): pins ≥32 silently truncate under 32-bit
shifts (reads as "button never presses", zero diagnostics). Covers poll
loop, debounce, boot-mode masks, hotkey masks, profile reinit. Each
converted site gets a hardware tap-test on a pin ≥32. Pico pins stay
<32, behavior identical.

## §3 Special-pin handling

Invalid (22–34) rejected everywhere pins enter (UI, migration import,
boot masks) — never stored, never polled. Reserved (19/20, 35–37,
43/44) storable-but-flagged with reason strings (Pico's reserved
concept). Note pins (0, 3/45/46) store normally with caveat text in UI.
Pixel unassigned by default; any valid pin arms it. Policy sets live in
`BoardConfig.h`, consumed generically.

## §4 Migration

One-shot (only board ever flashed): first boot extends stored 30-entry
tables to 48 (new slots unassigned, 0–29 preserved, checksum
recomputed). Forward-only. Verified by: configure on old build, flash
new, confirm intact + new pins selectable.

## §5 UI proof

API reports 48 → #1655 reflow renders GP0–GP48 minus invalid with
correct markers. Hardware: assign button to pin ≥35, save, reboot,
press, input registers. Regression: 0–29 mappings untouched, XInput
enumeration + boot-select instant.
